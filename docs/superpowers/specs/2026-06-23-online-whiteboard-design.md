# 온라인 화이트보드 — 설계 문서

- **작성일**: 2026-06-23
- **상태**: 설계 (리뷰 대기)
- **한 줄 요약**: 교육생이 **로그인 없이** 누구나 글·사진을 올리고, **실시간으로** 함께 채우는 Miro 스타일 무한 캔버스 화이트보드.

---

## 1. 목표와 배경

교육생들이 수업 중 또는 수업 후에 자유롭게 메모와 사진을 한 공간에 붙이며 협업한다.
가입·로그인 절차 없이 URL만 공유하면 바로 참여할 수 있어야 하고, 누군가 올린 내용이
다른 사람 화면에 즉시 나타나야 한다. 올린 내용은 영구 보관된다.

---

## 2. 브레인스토밍에서 확정된 결정

| 항목 | 결정 |
|------|------|
| 보드 형태 | **자유 캔버스** (포스트잇 벽 — 원하는 위치에 카드를 놓고 드래그로 이동) |
| 실시간성 | **즉시 반영** (WebSocket 기반) |
| 접속 환경 | **인터넷 어디서나** (URL 공유 / 클라우드 배포) |
| 보관 정책 | **영구 보관** |
| 보드 개수 | **여러 개** (보드마다 고유 코드·URL) |
| 인증 | **로그인 없음** — 브라우저 익명 ID 기준, **내가 올린 카드만 수정·삭제** |
| 비주얼 | **Miro 스타일** (무한 캔버스, 점 격자 배경, 스티키 노트, 떠 있는 툴바) |
| 툴바 위치 | **아래 중앙** (모바일 친화) |

## 3. 기술 스택

- **프론트엔드**: React 18 + Vite + TypeScript
- **백엔드(BaaS)**: Supabase
  - **Postgres** — 보드·카드 데이터
  - **Realtime** — `postgres_changes` 구독으로 카드 변경을 모든 접속자에게 전파
  - **Storage** — 업로드된 사진 파일
- **배포**: 프론트 = Vercel, 백엔드 = Supabase 클라우드(무료 티어)
- **스타일링**: Tailwind CSS *(확인 필요한 기본값 — §11)*
- **pan/zoom**: `react-zoom-pan-pinch` 라이브러리로 캔버스 변환 처리 *(확인 필요한 기본값 — §11)*
- **카드 드래그**: Pointer Events 기반 직접 구현(별도 DnD 라이브러리 없이)

## 4. 데이터 모델

### `boards`
| 컬럼 | 타입 | 설명 |
|------|------|------|
| `id` | uuid PK | 보드 식별자 |
| `code` | text UNIQUE | 짧은 공유 코드 (URL `/b/:code`에 사용, 자동 생성) |
| `title` | text | 보드 제목 |
| `created_at` | timestamptz, default now() | 생성 시각 |

### `cards`
| 컬럼 | 타입 | 설명 |
|------|------|------|
| `id` | uuid PK | 카드 식별자 |
| `board_id` | uuid FK → boards(id) ON DELETE CASCADE | 소속 보드 |
| `type` | text CHECK (`'text'`\|`'image'`) | 카드 종류 |
| `content` | text | 글 내용 (텍스트 카드) |
| `image_url` | text | 사진 공개 URL (사진 카드) |
| `x`, `y` | float8 | 캔버스 좌표 |
| `width`, `height` | float8 | 카드 크기 (사진 크기 조절용) |
| `color` | text | 카드 배경색 (스티키 노트 팔레트) |
| `owner_id` | text | 올린 사람의 익명 브라우저 ID |
| `z_index` | int | 겹침 순서 (맨 앞으로 가져오기용) |
| `created_at` / `updated_at` | timestamptz | 시각 |

## 5. 익명 신원 (로그인 없음)

- `useAnonId` 훅이 첫 방문 시 `crypto.randomUUID()`를 생성해 `localStorage`
  (`whiteboard_owner_id`)에 저장. 이후 항상 같은 ID를 반환.
- 카드 생성 시 `owner_id`에 이 ID를 기록.
- UI는 `card.owner_id === myId` 일 때만 **수정·색상 변경·삭제·크기 조절** 컨트롤을 노출.
- **알려진 한계(의도된 절충)**: 인증이 없으므로 `owner_id`는 클라이언트가 보내는 문자열일
  뿐, 서버에서 위변조를 막을 수 없다. 즉 권한 보호는 **신뢰 환경(같은 반) 전제의
  클라이언트 측 보호**다. 악의적 사용자가 API를 직접 호출하면 남의 카드도 바꿀 수 있다.
  교육용 신뢰 환경에 한해 허용하며, 이 한계를 문서에 남긴다.

## 6. 화면 구성 & 인터랙션

### 홈 (`/`)
- `새 보드 만들기` → 보드 생성 후 `/b/:code`로 이동
- `코드로 입장` 입력칸 → 해당 보드로 이동

### 보드 (`/b/:code`)
- **상단바**: 보드 제목(클릭 수정) · `공유`(URL 복사) · *(접속자 표시는 선택 — §12)*
- **캔버스**: 점 격자 배경. 빈 공간 드래그 = 이동(pan), 스크롤/핀치 = 확대·축소(zoom)
- **아래 중앙 툴바**: `🖐️ 이동` · `📝 메모` · `🖼️ 사진`
  - `메모` 선택 후 캔버스 클릭 → 그 자리에 빈 스티키 노트 생성 → 바로 입력
  - `사진` 선택 → 파일 선택 → 업로드 후 사진 카드 생성
- **카드 조작**
  - 드래그 이동: 누구나 가능
  - 내가 만든 카드: 텍스트 수정 / 색상 변경(노랑·분홍·파랑·초록) / 크기 조절(사진) / 삭제
  - 남의 카드: 보기·이동만

### 컴포넌트 구조
```
HomePage          보드 생성/입장
BoardPage         보드 로드 + 실시간 구독 + 캔버스 상태 보유
 ├─ TopBar        제목·접속자·공유
 ├─ Canvas        pan/zoom 되는 좌표 평면
 │   └─ Card      텍스트/사진 카드 (드래그, 소유자면 편집 컨트롤)
 └─ Toolbar       이동·메모·사진
hooks: useAnonId · useBoard · useRealtimeCards
lib:   supabaseClient
```

## 7. 실시간 동기화

- `BoardPage`가 마운트되면 `cards` 테이블의 `postgres_changes`를 `board_id` 필터로 구독.
- **INSERT / UPDATE / DELETE** 이벤트마다 로컬 카드 상태를 갱신(카드 `id` 기준 병합).
- **낙관적 업데이트(optimistic update)**: 내 조작은 로컬 상태에 즉시 반영하고 DB 쓰기는
  백그라운드로. 실시간 에코가 돌아오면 `id` 기준으로 조용히 정합화.
- **드래그 쓰기 절약**: 드래그 중에는 로컬만 갱신하고, 드롭 시 또는 ~100ms throttle로만
  `x/y`를 DB에 기록해 과도한 쓰기를 방지.
- **동시 편집**: `updated_at` 기준 last-write-wins. MVP 범위에서 충분.

---

## 8. 사진 업로드

- 허용: `image/*` (jpg, png, gif, webp), 최대 **5MB** *(확인 필요한 기본값 — §11)*.
- 업로드 전 클라이언트에서 큰 이미지를 최대 변 ~1600px로 다운스케일(canvas)해 저장·대역폭 절약.
- Supabase Storage 버킷 `card-images`에 `${boardId}/${uuid}.${ext}` 경로로 업로드 →
  공개 URL 획득 → `type='image'` 카드 생성.
- 버킷은 **공개 읽기**(public read).

## 9. 에러 처리

| 상황 | 처리 |
|------|------|
| 사진 업로드 실패 | 토스트 "사진 업로드에 실패했어요", 카드 생성 취소 |
| 용량 초과 / 잘못된 형식 | 업로드 전 차단 + 안내 메시지 |
| 실시간 연결 끊김 | Supabase 자동 재연결, "재연결 중…" 표시, 복구 시 카드 전체 refetch로 재동기화 |
| 잘못된 보드 코드 | "보드를 찾을 수 없어요" 화면 + 홈 링크 |
| 이동·수정 DB 쓰기 실패 | 낙관적 업데이트 롤백 + 토스트 |

## 10. 테스트

- **단위 (Vitest)**: `useAnonId`(ID 안정성·영속성), 소유권 판정(`canEdit`), 카드 상태 리듀서,
  이미지 검증(용량·형식), 코드 생성.
- **컴포넌트 (RTL)**: `Card`의 텍스트/사진 렌더링, 소유자에게만 편집 컨트롤 노출, `Toolbar` 동작.
- **통합**: Supabase 클라이언트 목으로 실시간 핸들러가 insert/update/delete에 상태를 갱신하는지.
- **수동 E2E**: 브라우저 2개로 같은 보드 → 추가·이동·삭제 실시간 동기화, 사진 업로드가 양쪽에
  보임, 잘못된 코드 → not-found 확인.

## 11. 확인 필요한 기본값 (단독으로 정한 기술 선택 — 리뷰 때 거부 가능)

- **스타일링 = Tailwind CSS** (대안: CSS Modules / vanilla CSS)
- **pan/zoom = `react-zoom-pan-pinch` 라이브러리** (대안: CSS transform 직접 구현)
- **사진 최대 5MB + 1600px 다운스케일** (수치 조정 가능)
- **권한 = RLS는 허용적, 소유권은 클라이언트 측**(신뢰 환경 전제, §5의 한계 수용)
- **동시 편집 = last-write-wins**

## 12. 범위 (YAGNI)

### 포함 (MVP)
- 여러 보드, 코드로 생성·입장
- 텍스트(스티키)·사진 카드, 색상 팔레트, 드래그 이동, 사진 크기 조절
- 실시간 동기화, 익명 소유권, 내 카드만 수정·삭제
- pan/zoom 캔버스, 공유 URL

### 제외 (MVP 아님)
- 계정·로그인
- 강사 관리자/모더레이션 도구 (— "내 카드만" 정책으로 대체)
- 댓글·반응·스레드
- 펜 드로잉·도형·연결선 (Miro의 그리기 기능)
- 내보내기·검색·실행취소(undo/redo)

### 선택 / 이후 (Optional, MVP 아님)
- 실시간 접속자 표시(presence 아바타) — Supabase Presence로 추후 추가 가능

## 13. 구축 순서 (대략)

1. 스캐폴드(Vite+React+TS, Tailwind, Supabase 클라이언트) + Supabase 스키마·버킷 생성
2. 홈: 보드 생성/입장
3. 보드: DB의 카드 정적 렌더 + pan/zoom 캔버스
4. 텍스트 카드 추가 + 수정·색상·삭제(소유자) + 익명 ID
5. 사진 카드 추가(업로드)
6. 실시간 동기화(구독·낙관적 업데이트·드래그 throttle)
7. 마감: Miro 스타일링, 토스트, 재연결 표시, not-found
8. 배포(Vercel + Supabase)
